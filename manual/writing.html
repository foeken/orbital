Chapter 3

Every line is a node

You write in Orbital the way you write in Tana: each line is a row, and rows nest under rows. By the end of this chapter you can shape an outline from the keyboard, link it to the rest of your workspace, and move it around with the mouse.

    Rows and markers

    A page is a title with rows under it. Every row is a node of its own: a block of the document you are in. A row with children has a thin guide line running down beside them.

    A page scrolls on past its last row, so the line you are typing at the end can sit in the middle of the window.

    Only list rows carry a marker. A bullet row has a dot, a numbered row its number. Text, headings, quotes and code have no marker, and their words start where the title's words start. Headings are darker than body text and open a new section with some space above them.

    1. Heading Three levels. No marker, darker words.
    2. Chevron Shows on hover beside a row with children. A click folds or unfolds it.
    3. Guide line Runs under a row's children.
    4. Mention A link to another node, drawn with its icon. More under References.
    5. Marks Bold, italic, strikethrough, code and links, inside a row.
    6. Quote A bar on the left, no marker.
    7. Code block Monospace on a grey panel.
    8. Numbered list Counts itself.
    9. Divider A thin line across the page.

    A folded row keeps its dot, drawn on a soft halo, so you can see it has children. A web address in a row is a link: click it and it opens in your browser. The words in Tana stay exactly as you typed them.

    When the caret is in a row you can type there; a row you cannot edit (a member, a meeting title, something read-only) shows a focus ring instead of a caret.

    Typing and the keys in a row

    There is no edit mode. Click a row and type. Orbital saves a moment after you stop, and again when you press ↩, leave the row or go somewhere else. A row in a view, like the Library, is a whole node: the first click selects it and the second puts the caret in (Views).

    Enter starts the next row ↩

    ↩ splits the row at the caret: what stands after the caret moves to a new row below. On a row that is open with children, the new row becomes its first child. At the very start of a row, ↩ puts an empty row in front of it instead.

    ⇧↩ adds a line break inside the row without starting a new one.

    Tab nests, Shift-Tab comes back out ⇥

    ⇥ tucks the row under the row above it. ⇧⇥ moves it back out, to just after its parent. On a plain line of text, ⇥ first turns it into a bullet; ⇧⇥ on a top-level bullet takes the bullet off again.

    Backspace at the start of a row ⌫

    At the start of a row, ⌫ works in small steps. First it takes the bullet off. If the row above is empty, that empty row goes. Otherwise the row's words join the row above, with the caret where they meet. An empty row is removed and the caret goes up. Nothing joins across an image, a table, a divider or a reference.

    Moving the caret

    ↑ and ↓ go to the row above or below and try to keep the caret at the same spot across. ← and → at the edge of a row carry on into the next one. From the first row, ↑ goes into the title. esc leaves the row.

    A new row takes after the row it came from: a bullet makes a bullet, a quote a quote, a numbered row the next number. After a heading or a code block, the next row is plain text.

    Markdown as you type

    You can shape a row by typing the markdown for it at the very start. The characters disappear and the row takes that shape in Tana.

    • - or * a bullet, 1. a numbered row
    • # , ## , ### a heading
    • > a quote, ``` a code block
    • [] or [ ] a checkbox
    • --- on an empty row: a divider

    Inside a row, a mark lands the moment you type its closing characters: **bold**, *italic*, ~~strike~~, `code` and [label](https://…) for a link. The caret stays just after the marked words, so what you type next is plain again.

    Pasting works the same way. Paste several lines, or text with markdown in it, and it arrives as real rows: headings, nested bullets, numbered rows, checkboxes, quotes, code and dividers, with the marks kept. One ⌘Z takes the whole paste back.

    A code block keeps what you type as text, so - or # stay as characters there.

    The toolbar, marks and block types

    Select some words in a row and a small toolbar floats above them. From left to right:

    • the style menu, which names the row's type and changes it
    • B bold ⌘B
    • I italic ⌘I
    • S strikethrough ⇧⌘S
    • <> code ⌘E
    • @ link the words to a node (see @ links)

    For a child row, Text stays in the menu but greyed out: in Tana a child has to be a list row. The mark keys work without the toolbar too, on whatever you have selected. esc hides the toolbar and keeps your selection.

    ⌘↩ turns any plain row into a checkbox, and ticks or unticks one that is already a checkbox. On a task it completes the task (see Tasks).

    Select a word →⌘B→⌘I

    The “/” menu

    Type / at the start of an empty row to choose what the row should be. Keep typing to narrow the list, then press ↩.

    Under Blocks: the headings, Bullet List, Numbered List, Checklist, Code Block, Quote, Divider, Table and Image. Image also answers to “picture”, “photo” and “upload”.

    Below the blocks come the things you can create: Doc, Task and the rest of what Create new … offers, with your workspace's own types under their own heading. Task asks for the task's name, makes it, and turns the row into a reference to it, as Tana's own “/” does. esc goes back to the list.

    @ links

    Select some words and type @. A small search drops down under them, already searching for your words. The @ itself is not typed.

    Pick a result with ↑ ↓ and ↩: your words become a link to that node. The first row is always Create “…”, which makes a new document with your words as its title and links to it (⌘↩). esc leaves your words as they were.

    Type @ with nothing selected and the same search opens empty, with the nodes you viewed recently first. What you pick goes in at the caret.

    Pasting a Tana link

    Copy a node's link (Copy link, ⌘C in ⌘K, or a link from Tana itself) and paste it into a row. It lands as a mention of that node, named after it. If the link cannot be read, the row stays as it was and a red note says why. Pasted into a title, an image or a divider, a link stays plain text.

    A page's title is plain text in Tana, so @ in a title puts the linked node's name there as words, not as a link.

    References and mentions

    A link to another node comes in two shapes, and which one you get depends only on what else is on the line.

    See Book the room

    Words around it: a mention, a link you clickAlone on its line: the node itself, box and all

    A mention sits among words. It is a blue link with the target's icon, and a click opens the target.

    A full reference is a row with nothing on it but the link. That row is the node it points at: it draws that node's bullet, tags and grey line, and a task shows its own checkbox, so you can tick it off right there. Rename the node anywhere and the row follows. Type anything else on the line and it becomes an ordinary row with a mention in it.

    1. A task, referenced Its own checkbox. Tick it here.
    2. A person, referenced Drawn with the member glyph.
    3. A folded row Its dot sits on a halo: there is more inside.
    4. Mentions Blue links among words, each with its target's icon: a person and a task here.
    5. A task from a meeting The meeting glyph links back to where it was decided.
    6. Web links Open in your browser.

    Working with a full reference: a first click selects the row, a second click puts the caret in it, and ↩ on the selected row starts typing at the end. The bullet or Space opens the node. Unfold it with its chevron or ⌘↓ and you see the node's own outline under a dashed guide line; what you type there is written into that node.

    When a node you link to is deleted, its links show it: a mention gets a trash glyph and a strike, and a full reference a trash bullet and a struck title. Neither opens. Undo the delete and they come back.

    Images

    There are three ways to add a picture, and all three end the same way:

    • Paste an image into a row. It lands just after that row.
    • “/” Image opens the file picker. Choose one file or several.
    • Drop files from the Finder. The drop line shows where they will land.

    Each file shows at once as a grey row with its name and “Uploading…”. They go up one at a time, and each grey row turns into the picture as it lands.

    Press esc on a grey row to cancel that file; the others carry on. Orbital takes the image types Tana does (PNG, JPEG, GIF, WebP, HEIC, AVIF, SVG, TIFF and a few more) up to 50 MB each, and skips anything else in a drop.

    On a picture, Space or a click opens it full size; esc, Space, ↩ or a click closes it. ⌫ or ⇧⌘⌫ removes it, and ↑ ↓ step over it.

    With the caret on a picture, ⌘K offers Process image: Orbital reads the picture and makes a task or a note from it.

    Drafts

    A page always ends in an empty draft row, so there is somewhere to type. It is drawn as what it will become, but it only exists in Tana once you type the first character. Leave it empty and it quietly goes away. ⌫ on it moves the caret up.

    Lists work the same way. In the Library, a view or a saved search, ↩ at the end of a row drafts a new document right under it. Type its title and press ↩ or move on: only then is it created, with all its words. esc or ⌫ on an empty draft throws it away.

    The draft takes after where you are. In a saved search of one type you get a node of that type. In a list grouped by responsibility you get a task set up for that group, the same as dropping a task there (see Tasks).

    Moving, folding and removing rows

    ⇧⌘↑ and ⇧⌘↓ move the row one step up or down among its siblings, children and all.

    ⌘↑ folds the row away and ⌘↓ unfolds it. The chevron beside the row does the same, and on a document row in a list ⌘K offers Collapse or Expand.

    ⇧⌘⌫ removes the row you are in with everything under it, wherever the caret is. The caret goes to the row before.

    Undo and redo

    ⌘Z undoes and ⇧⌘Z redoes. They are also Undo and Redo in ⌘K.

    There is one history for everything you change, across all documents. Each step is one thing you did: an ↩, a paste, a move. What you were typing is saved first, then undone as one step, and the caret goes back to the row it touched. Deleting a document is in the same history, so ⌘Z brings it back.

    Sharing and moving a document to a space are not undone this way: those you change back yourself.

    Selecting rows

    To work on several rows at once, select them. ⇧↓ and ⇧↑ grow the selection from the row you are in, and ⇧-click selects everything up to the row you click. ⌘-click adds or removes one row.

    ⇧↑ past the first row selects the parent, with all its children. ⇧↓ then gives back the selection you had, step by step.

    With rows selected, ⇧⌘↑ and ⇧⌘↓ move them together, ⇥ and ⇧⇥ nest and un-nest them, and ⇧⌘⌫ removes them. esc or a plain arrow key ends the selection. These keys never delete or move whole documents in a list.

    Drag and drop

    You can also move a row with the mouse. Pick it up by its marker (the dot, or the number) and drop it where a blue line shows it will land. Rows without a marker, like text and headings, show a small grip in the same spot when you point at them. An empty row cannot be picked up.

    One gap between two rows can mean several places. Move the pointer left and right: the line follows, starting where the words of that level start. Further right lands the row deeper; further left lands it higher up. The line only appears where the row can really land.

    The row moves whole, with its children. Where it lands, its parent opens so you can see it, and a parent left empty folds up. Dropping a row back where it was does nothing.

    What a drop does

    • Into a list, a line of text becomes a list row. A heading, code block or image refuses to become somebody's child.
    • A document from a list (a view, the Library, a saved search) lands as a full reference to it. The list itself keeps its own order.
    • Onto a meeting's row, the nodes you drag are pinned to that meeting, and a note says so.
    • Onto a chat's message box, the rows go into your message: documents as chips, other rows as their words (see Chats).
    • A task onto a group in a list grouped by responsibility changes what it is to match that group (see Tasks).

    A row cannot move to another document by dragging; a reference to a document can. A selection of several rows travels whole only into a chat; to move several rows, use ⇧⌘↑ ⇧⌘↓ and ⇥.

    Tables

    “/” Table puts a three by three table under the row, with a header row. Click a cell and type: the cell saves like any row.

    ⇥ and ⇧⇥ walk the cells in reading order. ↑ ↓ go up and down a column, and ← → at a cell's edge go to the next cell. Past the ends, you leave the table. esc selects the whole table as one row; there ↩ goes back into the first cell and ⌫ removes the table.

    With the caret in a cell, ⌘K has a Table group: Add row above, Add row below, Move row up, Move row down, Delete row, Add column left, Add column right, Move column left, Move column right and Delete column. Each is one undo step. Tana's rules hold, so the header row stays on top and the last row and column stay; a command that cannot run is shown greyed.

    Paste an image into a cell and it goes into that cell, after the text. The table as a whole moves, selects and deletes like any row, with ⇧⌘↑ ⇧⌘↓ or a drag.
