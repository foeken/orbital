# Tana data model (as observed, September 2026)

Everything below was read from live documents, the graph API and the web client's bundle. Field names are exact; anything marked *unverified* was inferred from code, not seen on the wire.

## 1. Identity

- **URIs**: `tana:<kind>:<ulid>` where the ULID is 26 lowercase Crockford-base32 chars (48-bit ms timestamp + 80 random bits; `node.js ulid()`). Kinds seen: `text`, `event`, `space`, `user-profile`, `type`, `chat`, `canvas`, `agent`, `skill`, `artifact`, `image`, `asset`, `collection`, `pin-map`, `org`, `calendar-subscription`. Provider-synced events may carry non-ULID ids (e.g. `tana:event:33q68…`, 26 chars but not time-ordered).
- **Org**: the sync stream wants the WorkOS id (`org_…`, JWT claim `org_id`); the org *document* is `tana:org:<ulid>` (`orgDocUri` from the session).
- **User**: `tana:user-profile:<ulid>`; the ULID equals the session's `userExternalId` (also JWT claim `urn:tana:user:id`).
- **Blocks** inside content have an 8-char lowercase alphanumeric `blockId` in `attributes`.

## 2. A document = one Loro doc with two root maps

### `data` (LoroMap) — metadata. Keys by kind

Common (all kinds): `type` ('text' | 'event' | 'space' | 'user-profile' | …), `title` (plain string, **no inline nodes**), `titleAutoGenerated` (bool, deleted when a human edits the title), `createdAt` (ms), `restricted` (bool), `participants` (LoroMap uri → { type: 'user', role: 'admin' | 'editor' | 'attendee' | 'organizer' }), `sharedPinDates` (LoroList of { type: 'plain', datetime: 'YYYY-MM-DD', pinnedAt }), `attributes` (LoroMap, typed-field values), `createdInUri` (chat/event it was created from), `entityTypeUri` (`tana:type:…` when typed).

The graph may expose organizer-like participant data, but the companion access helpers use `admin`/`editor` as organizer-level roles for calendar-connected events; `attendee` is accepted by the generic write check and is not sufficient for event sharing or deletion.

Task fields (a task is a text document with a state): `stateType` ∈ `proposed | open | closed | not_now` (UI: Inbox / In Progress / Completed / Later), `stateEnteredAt` (ms), `stateChangedBy` (user-profile uri), `stateWorkflowUri` + `stateWorkflowStateId` (custom workflow states; deleted when switching to a plain state), `assignedToUris` (LoroList of user-profile uris), `assignedToUrisChangedAt/By`.

Event (`type: 'event'`): `startTime`, `endTime` (ms; all-day = midnight-aligned whole days), `timezone` (server rewrites to 'UTC'), `origin` ('tana' | 'provider'), `location`, `description`, `organizer` { name, email }, `attendees` (LoroList of { name, email, role: 'required', partstat }), `externalId`, `calendarSubscriptionUri`, `providerViewApplied`, `actions` [{ platform, href }], `mode` ('external-meeting-provider' | …), `updatedAt`. A Tana-created event has none of the provider fields until the server adopts it (it adds `externalId`, `organizer`, a "Tana Meeting" action). **Event content is empty**; meeting notes are separate documents owned by the event.

User profile: `name`, `displayName`, `role`, `profileImageUri`, `pinnedCollectionUri` (`tana:collection:…`), `pinMapUri` (`tana:pin-map:…`), `versionIndexUri`.

Type (`tana:type:…`): `name`, `description`, `instructions`, `workflowUri`, `appliesTo`, `language`; colour in `appearance.hue`.

Org (`tana:org:…`): workspace settings (`approvedMcpServers`, `featurePolicy`, `memberUserProfileDocUris`, spaces list); not a document index.

### `appearance` (LoroMap, optional root)

`imageUri` (`tana:image:…`; avatar for profiles, cover image for documents) and `hue` (0–360; types). No icon/emoji/SVG field exists anywhere.

### `content` (LoroMap) — loro-prosemirror document

`{ nodeName: 'doc', attributes: LoroMap, children: LoroList }`. Empty map on fresh/event documents; `content.js rootKids()` creates the skeleton on first write.

Block node: `LoroMap { nodeName, attributes: LoroMap, children: LoroList }`. Names: `paragraph`, `heading` (`attributes.level`), `bulletList` / `orderedList` → `listItem` → first child `paragraph` + optional nested list, `blockquote`, `codeBlock`, `image` (`attributes.tanaUri` = `tana:image:…`, `displayWidth`/`displayHeight` optional, no alt). Inline children of a paragraph: `LoroText` runs (marks such as links live in the text delta) and `LoroMap { nodeName: 'mention', attributes: { label, tanaUri } }`.

Outline mapping used by `content.js`: a bare block is a node; a `listItem` is the node of its first paragraph, its remaining blocks are children; lists are transparent.

## 3. Graph view of a node (`GraphService.ListNodes` JSON)

`{ id, title, titleAutoGenerated, createTime, updateTime, state: { type, enteredAt, changedBy, workflowUri?, workflowStateId? }, assignedTo: [uri], entityType: 'tana:type:…', ownerUri, spaces: [uri], restricted, editors: { uri: { peerUserHash, editTime } }, participants: { uri: { type, role } }, calendarEvent: { externalId, startTime, endTime, location, organizer, attendees, roster, actionUrl, recurrenceId, mode }, appearance: { imageUri, hue }, userProfile: { name }, createdBy, archivedAt, linkSharing, typeDef, workflowDef, chat }`. Empty repeated fields are omitted in JSON.

ListNodesRequest filters: `nodeTypes` (valid: text, event, space, user-profile, type, chat, canvas, agent, skill, artifact, search), `entityTypes`, `nodeIds`, `ownerIds`, `spaceIds`, `assignedTo`, `unassigned`, `stateTypes`, `stateSelectors`, `textQuery` (full text, relevance via `SORT_FIELD_TEXT_RANK`), `eventStartTimeMin/Max`, `hasParticipantUris`, `exactParticipantUris`, `attendeeFilters`, `createdBy`, `modifiedByUser`, `includeProposals`, `includeArchived`, `restricted`, `linkShared`, `attributeFilters` (typed fields: refs, dateRanges, textMatches, numberRanges), `limit`, `mode` (`LIST_NODES_MODE_WITH_COUNT` for `totalCount`), `sortOptions` [{ field: SORT_FIELD_CREATE_TIME | UPDATE_TIME | TITLE | USER_LAST_MODIFIED_AT | TEXT_RANK | EVENT_START_TIME, direction: SORT_DIRECTION_ASCENDING | DESCENDING }]. There is **no title-match filter**; rank titles client-side.

Edges (`ListEdges`, `Traverse`): LINKS_TO, CREATED_IN, BELONGS_TO, ATTRIBUTE_LINKS_TO, INSTANCE_OF, ASSIGNED_TO, SUBTASK_OF, PART_OF_WORKFLOW, HAS_PROPOSAL, CREATED_BY, EDITED_BY, UPDATED_IN, USES_AGENT, HAS_PIN (event/space → doc, from `pinnedItems` only), ATTENDEE_OF, ATTENDED, PROPOSES_CHANGE_TO, COMMENTS_ON.

`GetOwnerChain(nodeId)` → `entries` nearest-first (self, then owner, owner's owner…), each { uri, restricted, accessible }. No owners = the user's "Library".

## 4. Pins

- Sidebar: `profile.data.pinnedCollectionUri` → `tana:collection:` doc whose root `tree` is a LoroTree; each node's `data` has `{ uri }` (a pinned doc) or `{ label }` (a folder). Order = tree order.
- Personal date pins: `profile.data.pinMapUri` → `tana:pin-map:` doc, `entries[docUri] = { pins: LoroList<LoroMap { type: 'plain', datetime: 'YYYY-MM-DD', pinnedAt }>, mutedPins: same }`.
- Shared date pins: `doc.data.sharedPinDates`, same element shape.
- Events/spaces: root `pinnedItems` MovableList of { uri, mode?: 'document' | 'embed' }.
All are plain Loro mutations; no dedicated RPC. Details: [../PINNING.md](../PINNING.md).

## 5. Assets

`GET https://home.tana.inc/api/general/images/by-uri/<encodeURIComponent(uri)>[?w=&h=&format=&quality=&fit=]` with the bearer token → 302 to a signed imgproxy URL on `images.tana.inc` plus a `Cloud-CDN-Cookie`; the signed URL is 403 without that cookie. `/images/<cid>` and `/files/<cid>/download` also exist (need the cid from the image document). Upload path not mapped.

## 6. Session and tokens

`GET https://home.tana.inc/api/auth/session` (cookie session, WorkOS login) → `{ authenticated, user, accessToken, sessionId, organizationId, orgDocUri, userExternalId, role, permissions, featureFlags }`. The access token is a 5-minute JWT (`iss https://login.tana.inc`, claims `org_id`, `urn:tana:org:id` (bare ULID), `urn:tana:user:id`, `sid`); `?refresh=true` mints a new one. The platform rejects MCP OAuth tokens (audience `…/mcp`).

## 7. What Tana does not store

Node icons (SVG/emoji), per-document colour, meeting notes inside events, a title with inline mentions (titles are strings). Anything like that must live app-side.

The companion's native title boundary is narrower than the data field: `node.setTitle` writes the plain `data.title` string and removes `titleAutoGenerated`, but it cannot represent an inline mention. The companion editability helper reports profiles and unsupported kinds as read-only, events as read-only because organizer/calendar write capability is not exposed, and unknown ACL state as unresolved rather than writable.
