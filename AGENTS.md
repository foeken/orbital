# AGENTS.md — guide for future agents

This repo is **Tana Companion**: a macOS Electron outliner over the *new* Tana (home.tana.inc), synced live through Tana's own (undocumented, v1alpha1) platform protocol. Read this file first, then the docs it points to. Keep changes small and plain (CommonJS, no bundler, no framework, no new dependencies unless a few lines cannot do it).

## Map

| Path | What |
|------|------|
| `main.js` | Electron main: window, IPC, views (Tasks / Meetings / Library / Chats / Members), refresh loop, search, create, pins, icons, filters. The only place that knows about "tasks". |
| `preload.js` | `window.api` surface for the renderer (contextBridge). |
| `renderer.js`, `index.html`, `styles.css`, `icons.js` | The outliner UI (one file, no framework). `icons.js` is generated by `scripts/build-icons.js`. |
| `tana-session.js` | Electron-only login: cookie session on home.tana.inc (WorkOS), access token from `GET /api/auth/session`, refresh before the 5-minute expiry. |
| `sdk/` | Generic Tana platform client, Electron-independent: `transport.js` (Connect + bearer + 401 retry), `graph.js` (ListNodes/ListEdges/Traverse/GetOwnerChain), `sync.js` (ServerSync stream, per-document bootstrap, live updates, reconnect), `document.js` (LoroDoc + UndoManager), `node.js` (data-map accessors, ulid, initDocument), `content.js` (outline ops over the loro-prosemirror content tree), `query.js` (search/#filter/task/library query builders), `pins.js` (sidebar/date pins), `proto/descriptors.js` (protobuf descriptors extracted from Tana's bundle, loaded at runtime). |
| `db.js` | SQLite cache (node:sqlite): view rows, custom icons, settings. |
| `scripts/` | `platform-cli.js` (Electron-run CLI for everything the SDK does), `sdk-check.js` + `db-check.js` (offline checks, `npm run check`), `build-icons.js`, `build-icon.js` (app icon). |
| `docs/` | `sdk/01…05` (SDK docs: overview, **data model**, API reference, recipes, gotchas — start here for anything Tana-side), `PLATFORM-PROTOCOL.md` (wire protocol, the source of truth), `PINNING.md`, `SDK.md` (original layering contract, historical), `OUTLINER.md` (UI contract with all addenda and keyboard rules), `mockups/`. |
| `TASKS.md` | Every user request and its status. Update it when you finish something. |

## How Tana works (the short version)

- Everything is a **Loro CRDT document** with a `data` map (title, type, stateType, assignedToUris, participants, …) and a `content` map in loro-prosemirror layout (`{ nodeName, attributes, children }`, text as LoroText, mentions as inline maps). Task states: `proposed | open | closed | not_now` (Inbox / In Progress / Completed / Later). Ids are `tana:<kind>:<26-char lowercase ULID>`; kinds seen: text, event, space, user-profile, type, chat, canvas, agent, skill, collection, pin-map, org.
- **Sync**: Connect-RPC at `https://home.tana.inc/platform`, service `tana.sync.v1alpha1.SyncService`: one `ServerSync` server stream per client (peer info, heartbeats every 15 s, live_document_update, resync_required) plus unary `ServerSyncCommand` (begin_document_sync → bootstrap → live_document_update, unsubscribe, document_action soft_delete). Creating a document = subscribing an unknown id with local ops (MISSING → push full snapshot). Details and the exact state machine: `docs/PLATFORM-PROTOCOL.md`.
- **Discovery/search**: `tana.graph.v1alpha1.GraphService.ListNodes` (nodeTypes, assignedTo, stateTypes, entityTypes, ownerIds, textQuery, event time window, sort). Owner chain (`GetOwnerChain`) gives a document's location (space/event); no owners = "Library". Type titles come from `nodeTypes: ['type']` nodes; members from `nodeTypes: ['user-profile']`.
- **Pins**: sidebar pins are a LoroTree in a private `tana:collection:` doc referenced by the user profile; date pins are in a `tana:pin-map:` doc; all written as normal live updates (`docs/PINNING.md`).
- **Auth**: the platform rejects MCP OAuth tokens (audience mismatch). The web session token from `/api/auth/session` works for everything. Tokens live 5 minutes; refresh with `?refresh=true`.
- **Not supported by Tana**: SVG/emoji icons on nodes (only `appearance.imageUri`/`hue`), so custom icons are app-local. Event documents have empty content; meeting notes live in linked documents.

## Working rules that saved us time

- Verify against Tana read-only first (`./node_modules/.bin/electron scripts/platform-cli.js …`); only write to the user's real data when the user asked for it, and prefer scratch documents (`create` + `delete`) or the user's own test items ("Test Pin").
- `npm run check` must pass before committing. Offline checks use `scripts/fixtures/task-snapshot.b64` (a real task snapshot) and an in-process fake SyncService.
- Renderer gotchas: `window.api` from contextBridge is a non-configurable global, so never declare a top-level `const api` in renderer.js (use `tana`); CSP is `default-src 'self'`, no inline scripts/styles; the renderer has an in-file mock used when `window.api` is undefined so the UI can be tested without the main process.
- Electron gotchas: set `app.setPath('userData', …)` **before** `ready` or cookie partitions move; dev runs always show "Electron" in the menu bar (macOS uses the bundle name), the packaged app (`npm run package`) shows "Tana Companion"; `@electron/packager` replaces `electron.icns` in place and warns about the optional `.icon` format (harmless). Never `pkill -f Electron` (kills VS Code and friends); target the app by bundle id or session.
- Loro gotchas: containers cannot be moved between lists (copy + delete); `LoroList.toArray()` returns container handles (use `toJSON()`); UndoManager merges steps within `mergeInterval` (we use 0); `setPeerId` must happen before the UndoManager exists.
- Work is split per file ownership when using sub-agents (renderer vs main/SDK) with the contract in `docs/OUTLINER.md`; keep the "keyboard first" rule.
- Tana's protocol is undocumented and can change with any deploy; if bootstrap or search suddenly fails, re-extract the descriptors from the current bundle (`https://home.tana.inc/assets/shared-*.js`, `Mr(` base64 blobs) and diff against `sdk/proto/descriptors.js`.

## Integration checks and newer contracts

- `npm run check` includes SDK/database checks plus renderer auth/behavior checks. Also test ordinary edit notifications in a mock Electron window; helper-only tests once incorrectly treated all changed ids as deletions.
- `onChanged(docId)` is an ordinary refresh, `onChanged(null)` a global/pin refresh, and `onRemoved(id)` an explicit deletion. Unpin is not deletion.
- Preserve `Node.editable === false` in renderer: member profiles and known read-only nodes cannot enter editors. Backend mutation handlers enforce the same restriction.
- `sdk/access.js` implements the verified sharing/move subset. Do not extend ACL or move semantics by guessing CRDT keys or assuming ownership grants access.
- New requests go in TASKS.md’s existing numbered table, with sequential numbers; repeated requests update the existing row. Orchestrator owns statuses; worker completion alone is not integrated verification.
