# AGENTS.md — guide for future agents

This repo is **Tana Companion**: a macOS Electron outliner over the *new* Tana (home.tana.inc), synced live through Tana's own (undocumented, v1alpha1) platform protocol. Read this file first, then the docs it points to. Keep changes small and plain (CommonJS, no bundler, no framework, no new dependencies unless a few lines cannot do it).

## Map

| Path | What |

| `main.js`, `main/` | The Electron main process. `main.js` is the process boundary only: windows (the outliner and the quick-add panel), menu, the global shortcut, the IPC table, boot, and the `TANA_MAIN_TEST` hook. Everything that knows Tana is in `main/`, CommonJS modules requiring each other without cycles: `state` (the one `S` object every module shares for what gets reassigned — client, me, win, session, status, active view — plus the caches, constants and `send`/`setStatus`/`scheduleRefresh`; views.js injects `S.refresh`) → `rows` (graph node → row/Node, hues, types, members, event meta) → `documents` (subscribe/op/mut, the cross-document undo stack, delete/restore, create, info, onChange, access context) → `related` (owner chain, space contents, fields, the meeting hub: write-up, call link, pins, outcomes, notes) and `views` (the six views' filters, the one query, refresh loop, search, hidden titles, `start`), `pins` (sidebar/date/hub pins, today and week nodes), `quickadd` (the quick-add panel's context and its one write, plus the shortcut and panel lifecycle, injected with electron rather than requiring it), `images`. `scripts/sdk-check.js` runs all of it in one vm context with a fake electron. ## How Tana works (the short version)

- Everything is a **Loro CRDT document** with a `data` map (title, type, stateType, assignedToUris, participants, …) and a `content` map in loro-prosemirror layout (`{ nodeName, attributes, children }`, text as LoroText, mentions as inline maps). Task states: `proposed | open | closed | not_now` (Inbox / In Progress / Completed / Later). Ids are `tana:<kind>:<26-char lowercase ULID>`; kinds seen: text, event, space, user-profile, type, chat, canvas, agent, skill, collection, pin-map, org, image, call, transcript, screen-share, guest-profile, **search**. Tana's own client (`shared-*.js`) keeps two groups apart: document kinds (text, event, chat, canvas, agent, skill, type, workflow, collection, contact, search, action, artifact, call, screen-share, calendar-subscription, mcp-integration, widget, widget-source, suggestion-log — this capture was truncated at the start, so treat it as incomplete) and system kinds (user-profile, guest-profile, org, pin-map, liveQuery, presence, user-inbox). A **saved search** (`tana:search:`) is a document holding a stored search definition that "runs exactly as stored"; types carry `searches: [{ uri, title, label, description }]` pointing at them, and they can be pinned to the sidebar. `liveQuery` is a *different* thing — a materialised query cache (`data.type: 'liveQuery'`, `queryType: 'nodes' | 'edges'`, `query`, `queryVersion`, `state: pending | ready | error`, `result`) — not a saved search.
- **Sync**: Connect-RPC at `https://home.tana.inc/platform`, service `tana.sync.v1alpha1.SyncService`: one `ServerSync` server stream per client (peer info, heartbeats every 15 s, live_document_update, resync_required) plus unary `ServerSyncCommand` (begin_document_sync → bootstrap → live_document_update, unsubscribe, document_action soft_delete). Creating a document = subscribing an unknown id with local ops (MISSING → push full snapshot). Details and the exact state machine: `docs/PLATFORM-PROTOCOL.md`.
- **Discovery/search**: `tana.graph.v1alpha1.GraphService.ListNodes` (nodeTypes, assignedTo, stateTypes, entityTypes, ownerIds, textQuery, event time window, sort). Owner chain (`GetOwnerChain`) gives a document's location (space/event); no owners = "Library". Type titles come from `nodeTypes: ['type']` nodes; members from `nodeTypes: ['user-profile']`. Inbox, Tasks, Meetings, Library, Chats and People are one screen with six preset filters over one such query (`docs/VIEWS.md`); each caches its own rows, so the row cache holds one row per (view, document).
- **Pins**: sidebar pins are a LoroTree in a private `tana:collection:` doc referenced by the user profile; date pins are in a `tana:pin-map:` doc; all written as normal live updates (`docs/PINNING.md`).
- **Auth**: the platform rejects MCP OAuth tokens (audience mismatch). The web session token from `/api/auth/session` works for everything. Tokens live 5 minutes; refresh with `?refresh=true`.
- **Not supported by Tana**: SVG/emoji icons on nodes (only `appearance.imageUri`/`hue`); the app no longer keeps icons of its own either. Event documents have empty content; meeting notes live in linked documents.
- **Chats** have no `content` outline either: the conversation is a LoroList at `data.messages` on the chat document, text is plain markdown in one LoroText with no marks, and mentions are `[label](tana:…)` links, so a chip needs no lookup. "Thought for N seconds" is `completedAt - sentAt` computed client-side, and "X accepted 1 change" is a human status-update message whose `attachmentUris` are the changed documents. Read only `data.messages`: a whole chat bootstraps to megabytes because tool output and the rendered system prompt are stored inline. `listNodes({ nodeTypes: ['chat'] })` returns only chats with no owner, so meeting-scoped and subagent chats cannot appear in the Chats view. Details in `docs/CHATS.md`.

## Working rules that saved us time

- Verify against Tana read-only first: `node scripts/platform-cli.js …` (**not** `./node_modules/.bin/electron …`). Electron's GUI process aborts inside AppKit's `_RegisterApplication` whenever it starts under the agent sandbox, because LaunchServices is unreachable there, and every such run left a macOS crash dialog behind; the CLI now re-execs Electron itself and refuses with exit 3 when `CODEX_SANDBOX` is set, so real data needs an escalated (unsandboxed) run. `npm start` and the packaged app are GUI Electron too and need the same escalation. Details and measurements: `docs/ELECTRON-SANDBOX.md`. Only write to the user's real data when the user asked for it, and prefer scratch documents (`create` + `delete`) or the user's own test items ("Test Pin").
- `npm run check` must pass before committing. Offline checks use `scripts/fixtures/task-snapshot.b64` (a synthetic task document with the same shape a real one has — link mark, heading, inline mention — rebuilt by `node scripts/fixtures/make-task-snapshot.js`; keep its constants in step with the ones at the top of `sdk-check.js`) and an in-process fake SyncService. Nobody's real Tana content belongs in this repo.
- Renderer gotchas: `window.api` from contextBridge is a non-configurable global, so never declare a top-level `const api` in the renderer (use `tana`, declared in `renderer/state.js`); CSP is `default-src 'self'`, no inline scripts/styles; `renderer/mock.js` is used when `window.api` is undefined so the UI can be tested without the main process. New renderer code goes in the file that owns the concern; a new concern is a new file added to `index.html` at the point in the order where everything it needs at load time already exists.
- Electron gotchas: set `app.setPath('userData', …)` **before** `ready` or cookie partitions move; macOS takes the app name from the bundle, not from `app.setName`, so a dev run used to show "Electron"; a `postinstall` step patches CFBundleName/CFBundleDisplayName in `node_modules/electron/dist/Electron.app` so both launch paths read "Tana Companion" (docs/APP-NAME.md); `@electron/packager` replaces `electron.icns` in place and warns about the optional `.icon` format (harmless). Never `pkill -f Electron` (kills VS Code and friends); target the app by bundle id or session.
- Loro gotchas: containers cannot be moved between lists (copy + delete); `LoroList.toArray()` returns container handles (use `toJSON()`); UndoManager merges steps within `mergeInterval` (we use 0); `setPeerId` must happen before the UndoManager exists.
- Work is split per file ownership when using sub-agents (renderer vs main/SDK) with the contract in `docs/OUTLINER.md`; keep the "keyboard first" rule.
- **`grep` here is ugrep, and it lies on big files.** On a multi-MB or very-long-line file (a downloaded Tana bundle, `sdk/proto/descriptors.js`, `icons.js`) it reports *no match* — exit 1, no error on stderr, so `|| echo ...` fallbacks read as "nothing found" rather than "the search never ran". It produced three false negatives in one session: "no `tana:search` in the bundle", "zero `\"search\"` strings" and "neither svg is referenced by build-icons.js", each wrong and each nearly reported as a finding. For anything over ~1 MB use node (`fs.readFileSync` + `indexOf`/`matchAll`), and be suspicious of any zero-hit result for a word that must exist.
- Tana's protocol is undocumented and can change with any deploy; if bootstrap or search suddenly fails, re-extract the descriptors from the current bundle (`https://home.tana.inc/assets/shared-*.js`, `Mr(` base64 blobs) and diff against `sdk/proto/descriptors.js`.

- Releasing (`npm run release`) signs with the Developer ID in the Keychain and notarizes through the `notarytool` profile, the same pair Meeting Notes uses; `@electron/osx-sign` and `@electron/notarize` come with the packager, so no new dependency and no secret in the repo. Signing every nested file with `--timestamp` takes minutes — let it finish. Never run two packager builds at once: the packager `rm -rf`s the shared `$TMPDIR/electron-packager` root at startup, so a second run deletes the first one's tree and the failure surfaces as `codesign: … locale.pak: No such file or directory` on a random file, which looks like a signing bug and is not one. A run killed part-way can also finish later and silently overwrite `dist/` with an unsigned build, so run `spctl --assess` on the bundle right before shipping it. The zip is published to the public `foeken/tana-companion-releases` repo; this source repo stays private.

- The packaged app ships the repo source, and `--ignore` in the `package` script — not `.gitignore` — decides what lands inside it: `dist`, `docs`, `.git`, `TASKS.md` and `AGENTS.md` are excluded and everything else in the working directory is copied in, including untracked files. Keep private files out of the tree before packaging.

## Integration checks and newer contracts

- `npm run check` includes SDK/database checks plus renderer auth/behavior checks. Also test ordinary edit notifications in a mock Electron window; helper-only tests once incorrectly treated all changed ids as deletions.
- `onChanged(docId, { meta })` is one document's change: the renderer patches that row from `doc:info` and keeps its cached metadata unless `meta` is true (main compares assignees, restriction and participants). `onChanged(null)` is a global/pin refresh: the refresh loop writes the active view's rows into the cache before sending it, so the renderer reloads roots and runs no second query. `onRemoved(id)` is an explicit deletion. Unpin is not deletion.
- Renderer rendering rules: `render()` is synchronous for user actions that need the DOM right after; anything that arrives on its own (metadata, pins, the rail, live updates, members) calls `renderSoon()`, which coalesces into one render per frame, and a metadata answer patches its own rows (`patchMeta`) instead of rendering. List rows are reused when `rowSig` is unchanged, so whatever a row is built from must be in that signature. Icons come from `iconNode` (a cloned template), not `innerHTML`.
- Preserve `Node.editable === false` in renderer: member profiles and known read-only nodes cannot enter editors. Backend mutation handlers enforce the same restriction.
- A built-in key is a palette row with an entry in `DEFAULT_HOTKEYS` (renderer/state.js): the document keydown handler finds the row by combo (`hotkeyFor`/`hotkeyIds`) and runs it through `runAction`, so it shows up in Cmd+K with its chip and can be re-recorded with Cmd+Shift+K. Only ⌘K, ⇧⌘K, the text-size keys, ⇧⌘⌫ and ⇧⌘↑/↓ are hard-coded (and listed in `RESERVED`). A key the outline handler answers to itself must compare against `hotkeyFor(id)` and preventDefault, which is what stops the document handler from running the row a second time.
- `sdk/access.js` implements the verified sharing/move subset. Do not extend ACL or move semantics by guessing CRDT keys or assuming ownership grants access.
- Quick add (docs/QUICK-ADD.md) composes existing operations only: `createDocument` for the task, `setAssignees` through `mut`, `pins.nodePin` for the meeting. A created task is never turned into a failure — a refused assignment or pin comes back beside the node, because throwing there invites a second submit and a second task.
- An event node proves *invited* and *scheduled* only. Attendance lives on its `tana:call:` document (same ULID, `data.ownerUri` back to the event): the `sessions` root holds one entry per live session and empties when the last participant leaves, `data.sessionLog` keeps the join/leave history. `sdk/calls.js` reads it (`currentCalls` answers "which meeting am I in right now"), `scripts/platform-cli.js incall` runs it live. Nothing in the graph says whether a participant is speaking or idle.
- New requests go in TASKS.md’s existing numbered table, with sequential numbers; repeated requests update the existing row. Orchestrator owns statuses; worker completion alone is not integrated verification.
